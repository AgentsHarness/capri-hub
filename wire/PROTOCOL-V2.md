# Capri host↔hub session protocol v2

Status: implemented by `capri-host` and `capri-hub` on the
`refactor/session-v2` branch. No backward compatibility with v1; host, hub
and FE ship together.

Scope: the session between `capri-host` and `capri-hub`. The browser-facing
`/ws/fe` wire keeps its current `seq` / `subscribed.seq` / `trimmed`
semantics. The relay request/response plane keeps its own chunking; only its
delivery proof moves onto the session ack.

## 0. Invariants

1. **seq** — each direction has one gapless, monotonically increasing frame
   sequence. A reliable frame is assigned its seq exactly once and never
   renumbered.
2. **watermark** — `ack=N` means every reliable frame with `seq <= N` has
   been applied. The receiver advances only over contiguous frames.
3. **generation** — absolute state carries a per-host monotonic `gen`.
   `gen` orders state across sessions; `seq` orders frames inside one
   session. They are never substituted for each other.
4. **placeholder** — when a payload is discarded, its seq is kept and the
   frame becomes `{"type":"trimmed",...}`. A hole is never opened.

## 1. Session identity

A session is `(hostId, epoch)`.

- `epoch` is generated by the host process at startup (random uint64,
  non-zero) and sent in `hello`.
- Same epoch on reconnect = resume. The host replays its unacked log from
  the hub's `ackUp`.
- New epoch = new sequence space. The hub resets the up watermark, the
  down sender, and the out-of-order buffers. The per-host `audience.gen`
  keeps increasing; it is not reset by an epoch change.
- `hello.resume.up` carries the retired high-water mark at the start of a
  new epoch. The hub seeds its up receiver with it, so the first live
  up-seq is `resume.up + 1`; events below it are history the FE rebuilds
  from host history. On a same-epoch resume the hub's own watermark is
  authoritative and `resume.up` is advisory.
- On an epoch change the hub broadcasts `{"type":"subscribed","host":ID,
  "seq":baseline}` to `/ws/fe` subscribers before fanning out any event of
  the new epoch, so the FE's existing `reconcileHostSeq` moves its watermark
  to the retired high-water mark. The baseline may be below what the old
  epoch delivered (a restarted host process restarts its event counter), and
  the FE resets its coordinate in either direction.
- The reset is enqueued on the host's fan-out queue, not delivered directly,
  so it cannot overtake work already queued for that host. Each queued item
  carries the epoch it was gated on; the drain delivers the reset (tagged
  with the new epoch) and drops items still tagged with a retired epoch. A
  dropped old-epoch event is safe: the FE rebuilds the transcript from host
  history, and delivering its stale seq behind the reset is worse — the FE
  would accept it and then drop every new-epoch event below it. Order is
  therefore: old-epoch items that were queued while still current → reset →
  new-epoch events; late old-epoch items are discarded. The queue's target
  host is carried beside the event, so the reset is not dressed up as a host
  event.

## 2. Frame envelope

Every host↔hub JSON frame has:

```json
{"v":2,"type":"...","seq":N,"ack":M}
```

- `seq` is present on reliable frames and absent (or 0) on unreliable ones.
- `ack` is present on every frame that can carry it. It acknowledges the
  opposite direction's reliable frames.
- `epoch` appears only in `hello` / `hello_ack`; every other frame belongs
  to the session's epoch implicitly. `hubBoot` appears only in `hello_ack`
  and identifies the hub process for the life of the session.

Reliable in the session seq space: `events`, `audience`, `request`.
Unreliable in that space: `hello`, `hello_ack`, `hb`, `respond`.

`respond` is reliable at the relay layer (per-request, chunked) and does not
consume the session seq space; its `seq` is 0. It still carries `ack` so it
can acknowledge `request` frames.

## 3. Handshake

Both transports use one shape: the host writes `hello` as the first frame.

### 3.1 Host → hub

```json
{"v":2,"type":"hello","epoch":7,"token":"...",
 "resume":{"up":41,"down":17},
 "caps":{"deflate":true}}
```

- `resume.up`: on a new epoch, the retired high-water mark (the last event
  seq that existed before this session; the first live event is
  `resume.up + 1`). On a same-epoch resume it is the highest up-seq the
  host believes the hub applied; the hub's own value wins.
- `resume.down`: the highest down-seq this host applied. On a same-epoch
  resume the hub advances its down sender's ack to it (never backwards),
  so frames the host already applied are not replayed. On a new epoch it is
  ignored: the down space restarts at 1.
- A fresh process starts both at 0.

### 3.2 Hub → host

```json
{"v":2,"type":"hello_ack","epoch":7,"hubBoot":9001,"ackUp":41,"ackDown":17,
 "audience":{"gen":33,"watchers":2,"all":false,"sessions":["s1"]},
 "liveness":{"keepalive":5,"idle":20},
 "limits":{"maxFrame":8388608,"maxRelayBody":29360128,"resumeWindow":1500},
 "caps":{"deflate":true}}
```

- `hubBoot` is the hub process's incarnation id, minted once at startup. A
  hub restart resets its relay request-id counter, so a reqId only names one
  request inside one `hubBoot`. The host keys its relay memo by
  `(hubBoot, reqId)`, drops entries of an older `hubBoot`, and never sends
  an answer to a session of another incarnation.
- `ackUp` / `ackDown` are authoritative. The host adopts them.
- `audience` is the current absolute state snapshot, taken under the hub
  lock at handshake time.
- `liveness` is in seconds. `idle` MUST be at least `2*keepalive`.
- `limits` replace the duplicated constants (`maxFrameBytes`,
  `replayFrameBudget`, `eventBufCap`, 28MB relay cap). `resumeWindow` is
  the receiver's parked-frame bound in both directions: each side builds
  its receiver with the window it was told, never with a package constant.
- `caps.deflate` echoes the host's offer. Compressed uplink frames are
  allowed only after this echo.

A missing mandatory field, including a zero `hubBoot`, is `close(protocol)`.

## 4. Reliable delivery

### 4.1 Sender

```go
type Sender struct {
    next  uint64 // next seq to assign
    acked uint64 // every seq <= acked is confirmed
    log   []Entry // (acked, next], in order
    bytes int
}
```

In the up direction one log entry is one **event**, and the event's own seq
is the session seq. An `events` frame is a transport batch of a contiguous
run of entries; the frame's `seq` is the first entry's seq. The hub accepts
each event in order, so its watermark has the same per-event meaning as the
FE's. In the down direction one log entry is one frame (audience/request).

- Assign: `next++`, stamp `seq`, append to `log`.
- Ack: `ack >= acked` drops every frame `<= ack`; `acked = max(acked, ack)`.
- Retransmit on RTO (`2*keepalive`, reset on ack progress): send every
  frame in `log` in order, starting at `acked+1`.
- No max-retry counter. The session idle timer ends a dead link.

### 4.2 Receiver

```go
type Receiver struct {
    acked uint64
    buf   map[uint64]Frame // at most resumeWindow frames
}
```

- `seq <= acked`: duplicate; apply nothing, still ack.
- `seq == acked+1`: apply, then drain contiguous buffered frames.
- `seq > acked+1`: park. If `len(buf) > resumeWindow`, close the session
  with `overflow`; the peer reconnects with the same epoch and replays from
  its log. The watermark MUST NOT jump. The window is the value the peer
  advertised in `hello_ack.limits.resumeWindow`, not a local constant.

### 4.3 Flow control / outbox

Per direction a byte budget (`maxInflightBytes`, derived from `limits`).
When the log exceeds it:

- droppable transcript payloads are replaced in place by `trimmed`
  placeholders;
- critical frames (`client_request`, turn terminals, control rails) are
  retained;
- if critical frames alone exceed the hard cap, close the session with
  `overflow`.

A placeholder keeps `seq` and `sessionId` when known; the FE already treats
`trimmed` as silent and rebuilds the transcript from host history.

There is no separate repair timer and no paused-ring reset. The unacked log
is the repair path.

## 5. Frames

### 5.1 `events` (host → hub, reliable)

```json
{"v":2,"type":"events","seq":100,"ack":17,
 "events":[{"type":"chunk","seq":100,...},{"type":"chunk","seq":101,...}]}
```

- The `events` array is one contiguous run: `events[i].seq == seq+i`.
- A batch that would contain a hole is split into contiguous runs; each run
  is its own frame. An upstream drop is repaired with placeholders before
  framing, so a hole never reaches the wire.
- The receiver accepts the run one event at a time; `ack` is the last event
  seq applied contiguously.
- A receiver that sees a non-contiguous run closes with `unreadable`. The
  frame carries no separate first-seq field.

### 5.2 `audience` (hub → host, reliable)

```json
{"v":2,"type":"audience","seq":12,"ack":100,
 "gen":34,"watchers":2,"all":false,"sessions":["s1","s2"]}
```

- Absolute state. `watchers` is the number of FE subscribers receiving this
  host's events; `watchers == 0` pauses event upload.
- `sessions` is the union of displayed sessions plus one level of subagent
  children. `all:true` means the audience cannot be narrowed; the host
  filters nothing.
- Apply when `gen >= lastGen`. Equal gen = duplicate: apply once, still ack.
- This single frame replaces `subscribers` and `viewing`, their two gens,
  their two ack paths and their two retransmit entries.

### 5.3 `request` (hub → host, reliable)

```json
{"v":2,"type":"request","seq":13,"ack":100,
 "reqId":"7","method":"POST","path":"/api/...","body":{}}
```

- Delivery is proven by the host's cumulative `ack`. The hub fails a
  request if its frame is not acked within the request ack deadline, which
  is `3*keepalive` (one RTO of `2*keepalive` to retransmit a lost frame plus
  one heartbeat of margin, so a single loss never fails a request the
  session repaired). It fails a request if no response arrives within
  `RelayTimeout` (45m).
- No "host sent any uplink frame since dispatch" heuristic.

### 5.4 `respond` (host → hub, relay plane)

Keep the current shape (`body` or base64 `chunk` + `more`). `reqId` routes
it. A `respond` frame carries:

- `status`: the HTTP status code of the relayed call, repeated on every
  chunk.
- `encoding`: absent for an inline `body`; `"base64"` for a `chunk`. Any
  other encoding is a per-request protocol error (the hub fails that
  request with 5xx and leaves the session alone), because the field has
  exactly one defined value today.

The final chunk closes the request. `respond` frames are not part of the
session seq log; the relay deadline owns their loss.

The request is acked by the session, but the answer is not. The host keeps a
completed answer (bounded by TTL and bytes) and resends it on the next
session that adopts a `hello_ack` with the same `hubBoot`; `respond` is
idempotent at the hub, which ignores a reqId it already resolved. An answer
completed while no session was live therefore still reaches the browser, and
nothing is re-executed.

### 5.5 `hb` (both directions, unreliable)

```json
{"v":2,"type":"hb","ack":100,
 "status":{"ready":true,"busy":false,"booting":false,"pendingCount":0,"port":8765}}
```

- Sent every `liveness.keepalive` seconds, and immediately after a receive
  gap that needs an ack.
- Any received frame resets the idle timer.
- `status` is a snapshot; a lost one is corrected by the next `hb`.
- No other liveness or state-ack frame exists.

### 5.6 Close

No JSON close frame. The transport carries a `CloseReason` enum:

`normal`, `shutdown`, `superseded`, `auth`, `protocol`, `liveness`,
`overflow`, `unreadable`.

WS maps each to a fixed `(code, reason)` pair; QUIC maps each to an
application error code. The host switches its reconnect policy on the enum,
never on a string.

## 6. Liveness

One time scale, advertised by the hub:

- `keepalive` (5s): `hb` cadence and the transport-native keepalive cadence
  (WS ping / QUIC keepalive). The transport keepalive exists for NAT and
  half-open sockets; it is not a protocol signal.
  - Limitation: the QUIC keepalive is a dial-time process constant (5s on
    the host, 10s on the hub) and cannot follow a non-default advertised
    `keepalive`; the `Transport.SetKeepalive` call is a no-op there. The
    session `idle` timer does follow the advertised value, so a non-default
    `keepalive` is still enforced as a protocol signal, just not as a
    transport one.
- `idle` (20s): either side closes with `liveness` after this long without
  any frame.
- Hub registry: online while a session is attached; offline on session
  close. No sweep and no separate watchdog. `lastSeen` survives only as a
  display/ordering stamp refreshed when a session attaches or detaches; no
  liveness decision reads it.
- Request deadline is RPC, not liveness: the request ack deadline is
  `3*keepalive` (one retransmit RTO of `2*keepalive` plus a heartbeat of
  margin) and `RelayTimeout` (45m).

## 7. Transports

One `Transport` interface:

```go
type Transport interface {
    Send([]byte) error
    Recv() ([]byte, error)
    Close(CloseReason) error
    SetKeepalive(time.Duration)
}
```

- **WebSocket**: one frame per text message, or one raw-deflate stream per
  binary message (same threshold/flags as today). The first frame is
  `hello`; capability headers are gone.
- **QUIC**: one bidirectional control stream; the first frame is `hello`.
  Request streams carry `respond` frames as today. The hub never writes on
  a request stream.
- Deflate negotiation rides `hello.caps.deflate` / `hello_ack.caps.deflate`.

## 8. Browser-facing behaviour

- `/ws/fe` frame shapes and `subscribed.seq` stay unchanged.
- The hub still stamps `hostId` / `hostName` and fans out per host.
- `trimmed` stays the only placeholder type; `resync` stays the slow-
  subscriber recovery.
- On epoch change the hub sends `subscribed{seq:baseline}` before new-epoch
  events. No FE change is required.

## 9. Kept performance work

- Raw event bytes (`json.RawMessage`) end to end.
- Per-host gap-pull ring with a byte cap.
- Relay chunking and per-request QUIC streams.
- Flate compression and the 256-byte floor.
- FE-side `EventSequencer` unchanged.
